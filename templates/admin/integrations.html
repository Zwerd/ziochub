Trellix EX / NX

Email Security (EX) and Network Security (NX) are grouped here. Use the buttons below to switch - no extra row of top-level tabs.

Email Security (EX)

Push approved YARA rules to Trellix Email Security using the product UI flow: JSON password login, then multipart/form-data POST to /ex/yara_rules_ng/upload_yara with fields yara_file, f_type, content_type.

If you already have a session cookie from the browser, paste it into Manual Cookie to skip login. Otherwise set username and password (login body: {"auth_method":"password","data":{"username","password"}}). Login path may differ by version - adjust if the default fails.

One row per appliance (host, paths, credentials or manual cookie). Leave password empty when saving to keep the stored password for that row.

Test uses saved targets and enable flag (save after editing).

Network Security (NX)

Appliance HTTPS root and wsapis version. Paths follow Trellix docs (add/remove; remove uses POST). These rows are expanded to generic HTTP targets and merged with your custom YARA list under Automations → YARA push when automation runs.

Used for NX tests here and for YARA pushes (same setting as on Automations → YARA push).

Cisco ESA - content dictionary sync

ZIoCHub logs in to the appliance, then adds or removes dictionary words automatically when analysts submit or revoke IOCs (and on expiry if enabled). You only set the API URL, credentials, TLS option, and which dictionary on the ESA maps to which IOC type.

Supported IOC types for ESA: Email, Domain, IP, URL - each row is one dictionary name (exactly as shown on the ESA) and one type. Other IOC types (e.g. Hash) are not sent to ESA.

No trailing slash. Must include /esa/api/v2.0 (or your appliance’s API root).

Must match the Secure Email API Guide for your deployment. Dictionary add/remove and “Test connection” use the same query string.

Required for Group mode (group_name query parameter).

Required for Machine mode (host_name query parameter).

Requires cleaner.py / systemd timer against the same database. If removal fails, the IOC is still deleted locally; check logs.

Use the exact dictionary name from the ESA UI. One IOC type per row; add multiple rows if you use several dictionaries.

Cortex XDR

Uses the Cortex XDR public API (same host as https://api-…paloaltonetworks.com): TIM indicators (tim_insert_jsons / disable_iocs) and, for Hash IOCs only, optional Action Center file block list (hash_exceptions/blocklist). When Enable is Yes, outbound IOC events call cortex_xdr_push_ioc_from_context in the background.

Requires Cortex outbound enabled. Adds to block list after TIM succeeds; removes on revoke. Public API path hash_exceptions/blocklist.

Test uses saved settings (save after changing URL or keys).

Google SecOps (Chronicle SIEM)

Outbound IOCs are written to a Google SecOps Data Table via Chronicle REST v1beta (dataTableRows:bulkCreate / list+delete on remove). Create a table with two string columns in order: indicator type slug, then value (e.g. domain, zwerd.com). Service account needs IAM such as chronicle.dataTableRows.bulkCreate and OAuth scopes https://www.googleapis.com/auth/chronicle plus malachite-ingestion (for the optional ingestion probe below).

From Google REST endpoints. If empty, host defaults to https://<location>-chronicle.googleapis.com when Location is set.

If empty, Customer ID is used as the Chronicle instance id in the resource path.

Resource id of the pre-created Data Table (the dataTables/{id} segment), not the display title.

Used only for Test connection (GET /v2/logtypes). Leave empty for default US ingestion host.

Test uses saved settings: validates OAuth, then GET the Data Table if configured, then ingestion logtypes.
